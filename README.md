# Homelab: Proxmox + VMs as code

```
ansible/
├── ansible.cfg
├── inventory/
│   ├── pve.ini                 # [proxmox] host
│   ├── group_vars/proxmox.yml  # Proxmox IP/user (+ role overrides)
│   └── k8s.ini                 # generated by Terraform (VMs)
├── playbook/
│   ├── infra.yml               # Proxmox host + VMs: -e target=...
│   ├── services.yml            # Docker services on VMs: -e service=...
│   └── frontend.yml            # UIs (not implemented yet)
└── roles/
    └── infra/                  # Proxmox host + VMs
        ├── defaults/main.yml
        ├── files/vendor.yaml   # cloud-init snippet
        └── tasks/
            ├── main.yml
            ├── host.yml        # repos, upgrade, storage, swappiness
            ├── template.yml    # Ubuntu template 9000
            ├── api_token.yml   # Terraform API user + token
            └── vms.yml         # terraform plan → safety check → apply
terraform/                      # VM definitions (sizes, IPs) — called by roles/infra
toolbox/Dockerfile              # Ansible + Terraform image for CI
ci/run.sh                       # what CI runs inside the toolbox
.github/workflows/homelab-deploy-infra.yml
```

| `target` | Runs |
|---|---|
| `infra` (default) | host setup + template + token + VMs |
| `infra-host` | host setup + template + token |
| `infra-vms` | VMs only (Terraform) |

Future automations: add a role under `ansible/roles/`, a play in
`playbook/services.yml` (or `frontend.yml`), and an option in its workflow.

delete its own runner. `local` keeps OS, snippets, backups and vm-runner's disk
(the `infra` role keeps "Disk image" allowed there).

## CI/CD

Push to the `dev` branch → GitHub builds a toolbox image (Ansible +
Terraform) → a self-hosted runner on **vm-runner (VM 104)** pulls it and runs
`ci/run.sh` → `playbook/infra.yml` (infra role). Workflow: `homelab-deploy-infra`.

One-time runner setup and repo variables: **[docs/ci-setup.md](docs/ci-setup.md)**

## Still manual (one time)

- Install Proxmox.
- Storage resize you already did (swap 4G, `lvextend` of `pve/data`).

## Where to run this

From your **laptop/PC** (macOS, Linux, or Windows WSL) — called the *controller*.
Later you can move this repo onto VM 103 and run it from there.

## 1. Install tools on the controller

```bash
# macOS
brew install ansible terraform

# Ubuntu / WSL
sudo apt install -y ansible
# Terraform: https://developer.hashicorp.com/terraform/install
```

## 2. SSH key + access to Proxmox as root

```bash
ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519
ssh-copy-id root@192.168.8.50        # your Proxmox IP
ssh root@192.168.8.50 pveversion     # should work without password
```

## 3. Edit your values

- `ansible/inventory/group_vars/proxmox.yml` → Proxmox IP
- `terraform/terraform.tfvars`:
  ```bash
  cp terraform/terraform.tfvars.example terraform/terraform.tfvars
  ```
  then set `pve_endpoint`, `pve_node`, `net_prefix`, `gateway`.

Check the node name with `hostname` on the Proxmox host (yours is `pve`).

## 4. Run

```bash
mv Makefile.example Makefile
make infra   # = cd ansible && ansible-playbook playbook/infra.yml -e target=infra
```

The `infra` role saves the API token to `terraform/pve-token.auto.tfvars`
(git-ignored) and runs Terraform for you. VM deletion/replacement is blocked
unless you add `-e infra_allow_destroy=true`.

The first `make vms` takes a few minutes: Terraform waits until each VM's
guest agent is running (installed by cloud-init on first boot).

## Day-to-day

| Want to | Do |
|---|---|
| Change RAM/CPU/disk | Edit `locals` in `terraform/main.tf`, `make vms` |
| Preview only | `make plan` |
| Rebuild everything | `make destroy` then `make vms` |
| Rebuild one VM | `cd terraform && terraform apply -replace='proxmox_virtual_environment_vm.vm["k8s-w1"]'` |
| Re-run host setup | `make host` (safe, idempotent) |
| Skip apt full-upgrade | `cd ansible && ansible-playbook playbook/infra.yml -e target=infra -e infra_full_upgrade=false` |
| Rebuild the template | `qm destroy 9000` on the host, then `make host` |

Disks can only **grow** in Terraform; shrinking a `disk` value fails.

## Notes

- The Terraform API user gets the `Administrator` role — fine for a homelab;
  tighten to a custom role later if you want least-privilege.
- Lost the token file? Just run `make host`: the role re-creates the token.
- If you already created VMs 100-103 by hand, delete them first
  (`qm stop <id>; qm destroy <id> --purge`) or Terraform will fail with "VM already exists".
